# Хетаг Дарчиев — Next.js + Go + PostgreSQL

Персональный сайт с серверным рендерингом и редактором контента. Сохранены фотографии, цветовая гамма, проекты, адаптивная вёрстка и анимации предыдущей версии.

## Быстрый запуск через Docker

Нужны Docker с Compose и Node.js для генерации настроек. Откройте терминал в корневой папке распакованного проекта:

```sh
node configure.mjs
docker compose up --build -d
```

Первая команда создаст `.env` со случайными паролями и покажет пароль администратора. Сохраните его. Повторный запуск не перезаписывает существующий `.env`.

- Сайт: http://localhost:3000
- Редактор: http://localhost:3000/admin
- Пароль редактора: значение `ADMIN_PASSWORD` в `.env` при **первом** запуске БД.

Открывайте именно `localhost`, а не `127.0.0.1`: проверка Origin использует `PUBLIC_ORIGIN`. При смене адреса измените это значение и пересоздайте сервисы.

```sh
docker compose logs -f
docker compose down
```

Обычная остановка сохраняет данные в Docker volume. Команда `docker compose down -v` удаляет базу — не используйте её для обычного перезапуска.

Без Node.js можно самостоятельно скопировать `.env.example` в `.env` и заменить оба пароля. Для пароля БД используйте случайные латинские буквы и цифры: он включается в URL подключения. Пароль администратора — от 12 до 72 байт UTF-8.

## Что умеет редактор

- Редактировать текст первого экрана и биографию.
- Добавлять, удалять и менять порядок категорий навыков и отдельных проектов.
- Менять описания, технологии, ссылки на исходники и демонстрации.
- Выгружать и загружать JSON-копию содержимого.
- Сохранять изменения в PostgreSQL; они становятся видны посетителям при следующем запросе страницы.

Контакты, имя, фотографии и структура секций пока задаются в компонентах. Панель не является визуальным конструктором всей страницы. Загрузка новых фотографий через панель не реализована.

Последние 50 предыдущих версий документа хранятся в `content_history`. Интерфейса просмотра этой истории пока нет. Для восстановления через интерфейс используйте заранее выгруженную JSON-копию. После загрузки копии нужно нажать «Сохранить изменения».

## Архитектура

```text
Браузер → Next.js :3000 → Go API :8080 → PostgreSQL :5432
                   │
                   └─ серверный рендеринг страницы
```

- `frontend/app/page.tsx`: серверная React-страница, данные запрашиваются без кэширования.
- `frontend/components/Content.tsx`: React-компоненты проектов и навыков.
- `frontend/components/Motion.tsx`: появления при прокрутке, движение портрета, индикатор чтения и отключение анимаций.
- `frontend/components/Admin.tsx`: редактор на React.
- `frontend/app/api/[...path]/route.ts`: ограниченный прокси к Go. Адрес API остаётся серверной настройкой, браузер работает с одним origin.
- `backend/main.go`: HTTP API, валидация, авторизация, работа с БД и миграции.
- `backend/schema.sql`: первая миграция.
- `backend/seed.json`: начальное содержание, вставляется только в пустую БД.

Контент хранится одним документом JSONB, поскольку сайт редактируется и сохраняется целиком. Администратор, сессии, версии и миграции находятся в отдельных таблицах. PostgreSQL является постоянным хранилищем; локальные JSON-файлы и localStorage не используются для сохранения редактором.

Пароль хранится как bcrypt-хеш. Cookie сессии имеет HttpOnly и SameSite=Strict; при HTTPS включается Secure. В БД сохраняется только SHA-256-хеш случайного токена сессии. Сессии живут 8 часов и переживают перезапуск API. Есть ограничение частоты входа, проверка Origin, лимит размера запроса и валидация HTTP(S)-ссылок. API и база не публикуют порты наружу в Compose.

`ADMIN_PASSWORD` создаёт администратора только при первом запуске. Его изменение в `.env` не меняет существующий пароль. При утрате пароля потребуется административный сброс хеша в БД; пользовательского сброса через email нет.

## Запуск без Docker

Нужны Node.js 22+, Go 1.25+ и PostgreSQL. Создайте отдельную БД и пользователя. Пример PowerShell для API:

```powershell
cd backend
$env:DATABASE_URL='postgres://USER:PASSWORD@localhost:5432/portfolio?sslmode=disable'
$env:ADMIN_PASSWORD='YOUR_LONG_RANDOM_PASSWORD'
$env:PUBLIC_ORIGIN='http://localhost:3000'
go mod download
go run .
```

В другом терминале:

```powershell
cd frontend
$env:API_URL='http://127.0.0.1:8080'
$env:PUBLIC_ORIGIN='http://localhost:3000'
npm ci
npm run dev
```

Для production-сборки: `npm run build`, затем `npm start`. На Linux создаётся standalone-сборка для Docker. На Windows используется обычный `next start`, чтобы избежать ограничений копирования файлов standalone в этой среде.

Для просмотра только дизайна без API можно явно включить `DEMO_MODE=true` при запуске frontend. Тогда страница использует начальный seed, а редактор по-прежнему требует API. В обычном режиме ошибки API не маскируются устаревшими данными.

## Проверки

```sh
cd frontend
npm ci
npm run build
npm run typecheck
```

```sh
cd backend
go test ./...
```

Для интеграционного Go-теста задайте `TEST_DATABASE_URL` отдельной тестовой PostgreSQL. Тест создаёт уникальную схему, проверяет миграцию, сессии, запись и историю, затем удаляет только свою схему. Не используйте production-БД для тестов.

В среде подготовки успешно выполнены:

- production-сборка Next.js и проверка TypeScript;
- Go-тесты авторизации, валидации, cookie, Origin и выхода;
- интеграционный тест с настоящим PostgreSQL 18.3;
- сквозная проверка Next.js → Go → PostgreSQL: вход через прокси, запись, отображение нового текста в HTML серверного рендеринга и выход;
- повторное подключение к БД с сохранёнными данными и проверка истории.

Docker-образы и Compose здесь не запускались: Docker в среде отсутствует. Визуальная проверка в браузере после переноса не выполнялась.

## Размещение в интернете

Проект подготовлен для VPS/контейнерного хостинга с Next.js, Go и PostgreSQL. Это исходники, а не уже опубликованный сайт. Sites на Cloudflare Workers не запускает обычный Go-сервис с TCP-подключением к PostgreSQL; для этой архитектуры нужен другой хостинг.

Настройте домен и HTTPS reverse proxy к `127.0.0.1:3000`, укажите точный HTTPS-origin в `PUBLIC_ORIGIN`, сохраните постоянный volume БД и настройте резервное копирование. Для внешнего PostgreSQL включите проверку TLS в `DATABASE_URL`. Не публикуйте `.env` и не открывайте порт БД всем посетителям.

Описания проектов взяты из предоставленных репозиториев. Личный вклад в командный Comunicore не выдуман. Портреты обработаны с помощью AI.

Документация используемых технологий: [Next.js](https://nextjs.org/docs/app/getting-started/installation), [pgxpool](https://pkg.go.dev/github.com/jackc/pgx/v5/pgxpool), [PostgreSQL Docker image](https://hub.docker.com/_/postgres).

## Обновление: темы, медиа и модули

Пересобрать оба сервиса: docker compose up -d --build api web. Миграции применяются автоматически. Пользовательские тексты не заменяются; позиционирование обновляется только для исходных текстов шаблона.

В /admin → Проекты можно загрузить или заменить обложку и логотип (PNG/JPEG, до 5 МБ и 20 мегапикселей), затем нажать «Сохранить изменения». Изображения хранятся в PostgreSQL, включайте всю базу в резервную копию. JSON-экспорт содержит только ссылки на изображения. Удаление изображения из карточки не удаляет файл из истории.

Архитектура: frontend/components/sections — секции страницы; components/admin — поля проектов и загрузка; lib/age.ts — возраст по московскому времени; app/refinements.css — финальная палитра и оформление. backend: main.go — запуск, http.go — API и сессии, models.go — валидация, repository.go — данные, media.go — изображения, migrations.go и schema*.sql — схема базы.
